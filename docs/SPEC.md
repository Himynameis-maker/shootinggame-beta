# Coin Mirror 仕様(AIに最初に読ませる)

## ゲームの流れ
1. **収集フェーズ**: 制限時間内に、ノルマ数のコインを弾で撃って取る。コインは「最大同時数」ずつ画面のランダム位置に出て、全部取った瞬間に次の束が出る。ノルマを全部取ると回避フェーズへ。時間切れはゲームオーバー。
2. **回避フェーズ**: 画面の反対側(左右反転)に、過去の自分たちが半透明の敵として現れ、記録された動きと弾を再生する。敵の体に当たり判定はなく、**敵の弾だけ**がダメージ。時間いっぱい生き残る。
3. **報酬**: 新しい弾/アイテムを3択から1つ取得。ここと右クリックのポーズ中に、弾のショートカット(上限8)を変更できる。
4. ラウンドが進むほどノルマと時間が増える。次の回避では、前までの収集・回避の記録が全部ゴーストとして入る(数は CFG.maxGhost で制限)。

## 設計メモ
- 記録は収集/回避それぞれ、毎フレームの位置と向き + 発射イベント(弾ID、位置、角度)。
- ゴーストの弾は x を左右反転(W - x)、角度は PI - a。
- 弾の fire() は自機とゴーストで共通。owner('p' か 'e')で当たり判定が変わる。
- 固定ステップ60Hzで更新。

## ファイル構成
index.html(読み込み順を管理) / js/config.js / js/core/* / js/lang/* / js/content/(bullets, items) / js/ui/* / js/main.js
新しい弾やアイテムは def('bullet'|'item', {...}) で追加し、js/lang/*.js の全言語に名前と説明を足す(README参照)。

## 敵(ゴースト)の弾のルール
- 敵の弾は**記録の再生だけ**。自機を狙う・追尾する・自機の位置に反応する挙動は作らない(今後も)。
- 曲がる弾(homing など)は、自機が撃ったときの軌跡を `trace:true` で丸ごと記録し、敵はその軌跡をそのまま再生する(敵側で再計算しない)。
- ビームなど発射の挙動が見えにくい弾は、弾定義に tele:長さ(px) を付ける。敵が撃つ1秒前(CFG.tele フレーム)から、その軌道(trace弾は記録した曲線)が薄い点線で予告表示される。

## 敵の弾の仕組み(軽量化の要)
- 回避フェーズの敵の弾・ビームは、記録を bakeRec() で「フレーム番号 → 位置」の表に変換して再生する(G.et)。弾を動かす更新処理はなく、`位置 = f(今のフレーム)` を引くだけ。
- 表は記録1つにつき1回だけ作ってキャッシュ(rec.bk)。報酬選択中(endDodge)に直前の記録を先に焼く。
- 直進系は fire() を1回だけ呼んで展開し、位置は式で出す。曲がる弾は trace:true で軌跡(Float32Array)を持つ。
- 弾の絵は spr() で色×大きさごとに1回だけ作り、drawImage で貼る。
- 敵の弾に新しい挙動を足すときも、「記録して表にする」形を守る(敵側で状態を持って動かさない)。

## AIへの依頼ルール
- 既存のファイル構成と書き方(クラシックscript、グローバル共有)を変えない。
- 変更したファイルは、パスを明記して**ファイル全文**で返す。変更のないファイルは返さない。
- 新しい文字列は ja/en の両方に足す。
- 絵は図形だけ(画像ファイルは使わない)。
- 不明点は、実装前に質問を1つだけする。
